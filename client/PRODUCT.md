# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

个人开发者、重度使用多个 AI 编码 Agent（Cursor / Claude Code / TRAE / CodeBuddy / Codex / Qoder / Windsurf…）的人。典型场景：在多个提供免费或不同额度 token 的 Agent 之间来回切换，本机散落着十几套技能目录；他们需要一个本地页面，回答「我有哪些技能」「这条技能现在在哪些目录里生效」「换 Agent 时怎么把技能一次性带过去」。

## Product Purpose

把本地 skill 变成可管理的个人资产：一处沉淀、可检索、可打标签、可去重，并按预设 / 标签一次性投放到任意 Agent 或项目目录。成功的样子是：用户不再手工在十几个目录里复制粘贴，也不再记不清哪条技能落到了哪里。

## Positioning

**文件系统即唯一事实源**。没有数据库里的期望集，没有后台自动同步：界面上看到的「哪个目录装了什么」就是磁盘上的真实状态；投放与移除只在用户显式操作时发生。这条机制是同类「技能市场 / 配置中心」产品无法照搬的——它们必须维护一份自己的清单。

## Operating Context

- 本机运行的本地 Web 应用（`127.0.0.1:8787`，由 `npx flint-skills-hub` / `start.sh` 拉起），通常在编辑器与终端旁边开着，看屏幕的时间点既有白天也有深夜。
- 数据规模真实且大：约 120 条技能、59 个内置 Agent 目录、多个预设与项目。
- 用户熟练于终端语汇：路径、软链 / 副本、`~/. agents/skills`、`name@来源`。
- 详情页承载判断与排障（正文、标签、内容体检、投放位置），列表页承载定位与批量操作。

## Capabilities and Constraints

- 六类对象：技能（含来源 / 版本 / 标签 / 体检结论）、Agent 目录（同目录多 Agent 合并、主 Agent）、预设（显式成员 ∪ 标签命中）、项目（`.agents` 真实副本）、仓库 / 第三方只读来源、诊断。
- 核心状态语汇：活跃 / 非活跃、软链 / 复制、已接管 / 自管、只读、失效软链、重复技能、仅扁平、按标签纳入。
- 约束：技能本体永不进入配置文件；不替换外部软链；不自动补回被删技能；一目录一套策略。
- 交付物是「工具界面」，不是营销站点：不存在首页 hero、定价或获客路径。

## Brand Commitments

- 名称 **Flint**（燧石），仓库名 `local-skills-hub`，包名 `flint-skills-hub`；界面文案中文优先、可切英文（`i18n/zh.ts` / `en.ts`）。
- 产品性格：克制、诚实（计数写「0 / 120」，不粉饰）、把副作用讲清楚；不喧哗、不游戏化。
- 既有视觉词汇不做承诺：现有蓝灰 SaaS 外观是历史实现，不是品牌资产；重设计可整体替换，但名称、文案与操作流程不动。

## Evidence on Hand

- 真实数据与文案在 `server` 与 `client/src/i18n/*.ts`；设计评审记录在 `.impeccable/critique/`；产品需求 `docs/PRD.md`。
- 无客户 logo、无营销素材、无价格与性能基准；任何新增界面都不得伪造这类主张。

## Product Principles

1. **物理为准**：界面上的每一条状态都要能指回磁盘上的一个真实落点。
2. **决策可逆地可见**：写入前说清范围，写入后不假装有后台在兜底。
3. **数量诚实**：计数、筛选结果、未安装目录都照实呈现，不隐瞒也不夸大。
4. **熟练者优先**：路径、标识、键盘与密度服务于每天用它的开发者，其次才是第一次来的人。
5. **安静的力量**：科技感来自精度与秩序（对齐、刻度、等宽数据），不来自装饰。

## Accessibility & Inclusion

- 正文对比度 ≥ 4.5:1（此前次要文字 `#8b90a5` 仅约 3.2:1，属待修复缺陷）；状态不能只靠颜色区分。
- 键盘可达：焦点环清晰可见；模态需限制焦点；图标按钮必须有可访问名称。
- 中文与英文两套文案等长可用，不因语言切换破坏排版。
